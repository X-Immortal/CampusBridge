## 2. 干了什么（按交付物）

### 2.1 五类人物与 18 条微需求

- 文件：`docs/M1-needs.md`
- 5 类人物：行动不便学生、上课学生、新生、留学生、社团负责人；每类都写了目标、情境、约束、未知、成功证据、生成什么交互、数据保留范围。
- 18 条微需求：每条带用户原话（不润色）、来源、类型（稳定/偏好/一次性）、状态、责任人、验证证据。
- 关键设计：**同一个“取快递”，五类人要五种卡片、五种第一句追问、五种成功证据**，不是换名字填同一张表。
- 证据强度如实标注：P1 有 1 条近似临时证据、P2 有 3 条近似、P3/P4 **0 条直接证据**、P5 只有 1 条弱信号。

### 2.2 访谈记录

- 文件：`docs/M1-interviews.md`
- 4 份 2026 春 P1 阶段二手记录、7 人次、51 问；A 是第三人称转述、B/D 保留第一人称、C 是问答摘要。
- 2026-11-16 决定：选修课不要求新增真实访谈，原计划“本学期 ≥3 场”取消；二手记录继续用于需求溯源，**不冒充本学期 FDE**。
- 最大缺口：没有一个人是 P4（留学生），也没有长期行动不便者；P3（新生）也没有直接访谈。

### 2.3 本体 V0.1

- 真身：`backend/src/main/resources/ontology/campus-ontology.v1.json`
- 文档：`docs/M1-ontology.md`（由 `scripts/gen-ontology-doc.mjs` 生成，手改会被覆盖）
- 规模：20 概念 / 23 关系 / 15 约束；每个概念有定义、正例、反例。
- 运行时：`GET /api/ontology` 返回计数与指纹；`POST /api/ontology/reload` 不重启热更新。
- 硬校验：数量不达标、概念缺定义/例子/反例、关系引用不存在的概念、约束引用未实现的求值器 → **启动失败**（`OntologyRegistryTest` 守着）。

### 2.4 1.0 接管审计

- 文件：`docs/M1-baseline-audit.md`
- 对象：上学期 CampusBridge 1.0（192 次提交、143 个测试）。
- 五个问题：需求是否硬编码、状态谁改/是否可追溯、“完成/取消/信用”含义、哪些规则只在页面/人脑、哪些行为没记录。
- 结论：**1.0 业务内核不动**，外面套“能说话的皮”（Agent）和“能收口的闸”（Policy/Tool Gateway）。
- 保留：19 个实体、20 组 MyBatis、认证鉴权、接单/完成/内容审核、143 个测试。
- 改造：状态类型、乐观锁版本、分类进本体、规则进 Policy、完成/取消拆分、信用带 ruleId。
- 新增：Agent、Model Gateway、Tool Gateway、本体+Policy、UI Schema、事件表、鸿蒙端、评测集。

### 2.5 可运行 Agent Harness

链路：`POST /api/assistant` → 追问 → 比较 → 确认 → `ToolGateway` → 业务落库。

关键组件：

| 组件 | 作用 | 证据 |
|---|---|---|
| `AgentOrchestrator` | 把理解/澄清/提案/确认/工具串成状态机 | `AgentFlowTest` 5 条 |
| `RuleModelClient` | 规则基线，不编没说的字段 | `RuleModelClientTest` |
| `ModelGateway` | rule / llm / auto 可切，挂了降级并标 `degraded` | `AgentFlowTest#模型不可用时降级但仍然能出卡片` |
| `ClarificationPolicy` | 独立追问 Policy，最多 3 问 | `AgentFlowTest` 两轮追问 |
| `PolicyEngine` + 本体 | 约束在 Action 执行前求值 | `PolicyEngineTest` 19 条 |
| `SchemaValidator` | 白名单/字段/确认/令牌摘要 | `SchemaValidatorTest` 7 条 |
| `CardFactory` | 四类卡片 | 截图 02–05 |
| `ToolGateway` | 确认令牌 + 幂等 + 审计 | `AgentFlowTest#确认后建单_重复确认不再建单` |

红线：**候选 ≠ 事实**；确认前不写业务库；旧卡因版本失效；工具失败不写“成功事实”。

### 2.6 四类卡片与三条流程

- 澄清：缺时间/地点/报酬时只问缺的，每个 Field 带“为什么问”。
- 比较：三种找人方式（立即匹配/熟人优先/约时间）。
- 确认：摘要每行标「用户说的 / 系统推测」，带令牌。
- 进度：真实进展，不伪造完成。
- 三条流程：缺信息先追问、完整目标直接比较、用户撤销；对应 `AgentFlowTest` 与 18 条评测。

### 2.7 评测、失败库、AI 台账

- 评测：M1 时 18 条、八类覆盖，`node evals/run.mjs --live` → 18/18；当前分支扩到 40 条并接 M2 流断言 → 40/40。

- 证据：`evidence/M1/screenshots/01–05`、`evidence/M1/logs/k13-*.log`、`evidence/M1/eval-report.json`。

## 6. 现场可能被问的三题

1. **“你们访谈是真的吗？”**
   不是本学期新访谈，是 2026 春 P1 阶段 4 份二手记录、7 人次；A 是转述、B/D 是逐字、C 是摘要。P3/P4 没有直接证据，我们写在 `M1-needs.md` 里，不装。
2. **“本体真的在起作用，还是文档？”**
   现场改 `campus-ontology.v1.json` 里 K09 的 `min` 5→20，`POST /api/ontology/reload`，再确认同一张卡 → 409 `K09`；改回去再 reload → 又能建单。`PolicyEngineTest` 19 条一条对应一条约束。
3. **“模型和规则到底谁在干活？”**
   默认规则基线；`ai.model.mode=rule/llm/auto` 可切，没 key 时 llm 会带 `degraded=true` 退回规则；两种都走同一个 `ModelUnderstanding`，卡片和确认链路不变。
