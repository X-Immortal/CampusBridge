# 架构候选方案对比表

## 1. 项目背景与约束

CampusBridge 是一个面向校内互助场景的 Web 平台，当前已确定的现实约束包括：

- 前端采用 Vue 3 + Vite，后端采用 Spring Boot 3，天然适合前后端分离的 Web 交互模式。
- 在 10 周内完成，优先交付“认证 - 发布 - 搜索筛选 - 站内沟通 - 接单 - 完成确认 - 评价举报”的核心闭环。
- 当前团队规模较小，代码仓库与工程结构已经是单仓库、单后端服务骨架，尚未形成多服务运维体系。
- 平台需要一定可扩展性，后续可能增加信用、审核、推荐、通知、日志审计等能力，但当前阶段更强调可实现性与可维护性。

## 2. 候选架构方案分析

### 2.1 MVC

MVC 的优势在于把用户交互拆成 Model、View、Controller，特别适合 Web 界面开发。对于 CampusBridge 来说，它有助于理清前端页面展示、请求处理和业务数据之间的边界。

但根据课件，MVC 更适合作为“交互层/展示层”的组织方式，而不是整个系统的主架构。单独把 MVC 当成全系统架构，会弱化后端业务层、数据访问层、审核治理、日志等职责划分，不利于后续扩展。

### 2.2 分层架构

分层架构通常将系统拆成展示层、业务逻辑层、数据访问层，职责边界清晰，符合 Spring Boot 项目的常见组织方式。CampusBridge 当前后端骨架中已经出现了 `controller`、`service`、`mapper`、`entity` 等典型分层结构方向，因此继续采用分层架构成本最低。

分层也更适合课程项目节奏。它便于团队并行开发、接口联调、单元测试和后续文档表达，同时还能为认证、任务、消息、评价、审核等模块继续细分提供基础。

### 2.3 微服务架构

微服务强调服务独立部署、独立扩展、服务间通过 REST 或消息队列通信，确实适合大规模平台。但 CampusBridge 当前仍处于项目早期阶段，业务量、团队规模、部署资源和 DevOps 能力都不足以支撑微服务带来的额外复杂度。

如果过早拆成用户服务、任务服务、消息服务、审核服务等多个微服务，会引入网关、注册发现、服务调用、分布式事务、链路追踪、部署编排等问题。对于 10 周课程项目，这些成本很可能超过收益。

### 2.4 事件驱动架构

事件驱动架构适合处理异步通知、状态广播、解耦扩展等需求。例如 CampusBridge 未来的“任务状态变更通知”“举报触发审核”“积分变更日志”“消息提醒”等场景，都很适合事件驱动。

但如果把整个系统一开始就设计成以事件总线为核心的主架构，会让控制流变得更难追踪，调试和测试复杂度提高。对于当前以事务型业务闭环为主的平台，事件驱动更适合作为局部补充，而不适合作为当前主架构。

## 3. 架构方案对比表

| 对比维度 | MVC | 分层架构 | 微服务架构 | 事件驱动架构 |
|---|---|---|---|---|
| 开发复杂度 | 中。前端交互组织清晰，但若把它当成全系统主架构，后端职责仍容易混杂。 | 低。与当前 Spring Boot + Vue 工程形态最贴合，容易直接落地。 | 高。需要额外处理服务拆分、接口治理、部署与运维问题。 | 高。事件流、异步一致性、调试追踪都会增加实现复杂度。 |
| 可维护性 | 中。适合管理界面与交互逻辑，但对复杂业务域的纵向分层支持有限。 | 高。职责边界清楚，便于定位问题、重构模块和编写文档。 | 中。单个服务可维护，但整体系统维护成本高，依赖治理复杂。 | 中。模块解耦较好，但事件链较长时排障困难。 |
| 可扩展性 | 中。适合扩展页面和交互，不擅长支撑大规模业务演化。 | 高。适合在单体内部继续拆分任务、用户、消息、评价、审核等模块。 | 很高。适合高并发、多团队、独立部署的长期演化场景。 | 高。适合后续增加通知、审计、推荐等异步能力。 |
| 性能 | 中。对 Web 交互性能有帮助，但不直接解决系统级吞吐问题。 | 中到高。单体内调用链短，数据库事务处理直接，当前阶段足够。 | 中。可按服务独立扩容，但远程调用和网络开销会增加延迟。 | 中到高。异步处理吞吐潜力大，但事务型流程不一定更快。 |
| 团队学习成本 | 低。成员容易理解，特别适合前端页面开发。 | 低。最符合课程项目和常见企业 Java Web 开发经验。 | 高。需要掌握服务拆分、网关、消息、容错、监控等额外知识。 | 中到高。需要理解事件模型、幂等、补偿、最终一致性等概念。 |
| 10 周内可行性 | 中。适合做展示层设计，但单独作为主架构不够完整。 | 很高。最容易在当前时间、人力和代码基础上交付完整版本。 | 低。投入大量时间在基础设施而非业务闭环上，风险较高。 | 中。适合局部引入，不适合作为当前唯一主架构。 |
