## 2. AI 助力分析

### AI 在编码中最有价值的场景

AI 最适合生成结构明确、规则可枚举的代码，例如任务状态机、统一异常处理、DTO 转换、前端表单校验和 API 封装。它能快速给出第一版骨架，减少重复劳动。

### AI 在测试生成中最有价值的场景

AI 对边界条件枚举很有帮助，尤其是：

- 未登录/未认证访问
- 重复接单
- 非法状态流转
- 空字段和超长字段
- 举报和裁决的异常输入

但 AI 生成的测试有时只验证“方法被调用”，没有断言关键业务结果，需要人工补充断言。

### AI 在调试中最有价值的场景

AI 对日志和失败断言的定位效率较高。本阶段 `npm run test:admin` 失败后，AI 能快速建议搜索“管理后台/管理中心”，并指出页面 active label 与侧边栏 label 不一致。

## 3. AI 误导分析

### AI 代码信任度实验数据摘要

- AI 直出的测试通过率：约 80%
- 人工审查修复后的测试通过率：100%
- 发现的主要问题类型：
  - 未使用项目统一枚举和错误码
  - 权限校验不完整
  - 状态历史和通知副作用遗漏
  - 未处理异常路径和边界条件

### AI 调试对决实验总结

- AI 擅长调试的 Bug 类型：日志明确、断言明确、命名不一致、接口路径不一致、配置项冲突
- AI 不擅长调试的 Bug 类型：需要业务取舍、需要判断是否降级实现、需要权衡兼容性的接口设计问题
- AI 修复方案的典型问题：容易建议“直接改成文档一致”，但不一定考虑当前前后端已联通的实际路径

## 4. Prompt 改进计划

### 上阶段改进措施的验证结果

P3 阶段后团队要求 Prompt 必须附带“项目约束”和“不要自造接口”。P4 证明该方式有效：AI 输出更容易贴合已有 Controller、Service、Mapper 和 DTO。

### 编码阶段 Prompt 最佳实践

```text
请先阅读以下现有类/接口，再生成代码：
1. 当前模块 Service 接口
2. 相关 DTO 和枚举
3. Mapper 方法签名
4. ErrorCode 和统一异常处理

生成代码时不要新增未说明的框架，不要改变已有 API 路径。
```

### 调试阶段 Prompt 最佳实践

```text
这是失败命令、完整错误日志、失败测试文件和相关源码。
请先定位最可能的 3 个原因，再说明每个原因需要检查的文件。
不要直接给大范围重构方案，优先给最小修复。
```

### 下阶段计划改进

- 要求 AI 输出“假设清单”，明确它假设了哪些接口或数据结构
- 要求 AI 在生成测试时说明每个断言覆盖的业务规则
- 对 AI 给出的修复建议增加“是否影响演示主流程”的判断

## 5. 本阶段的核心工程判断

### 决策内容

本阶段选择优先完成 P0 主流程和 P1 基本能力，对部分 P2 功能延期，对敏感任务审核、通知中心和推荐能力做降级处理。

### 为什么 AI 无法单独做这个决策

AI 可以列出功能缺口，但无法知道课程验收重点、团队剩余时间、演示风险和每个成员的实际开发能力。比如敏感任务是进入审核还是直接拦截，既是技术问题，也是合规和演示取舍问题。

### 团队最终如何判断和取舍

团队按以下优先级决策：

1. 必须保证注册、认证、发布、接单、完成、评价、举报可演示。
2. 会影响核心流程的 Bug 必须修复。
3. P1 功能允许使用简化实现，但必须在文档中说明。
4. P2 功能不影响主流程时可以延期。
