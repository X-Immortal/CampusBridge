# CampusBridge 核心类设计修改稿

## 1. 修改背景

原始草案将 CampusBridge 的核心抽象建模为 `Task`，默认用户主要是在“发布任务”和“承接任务”。经过进一步讨论，这种抽象存在明显局限：

1. 校园互助平台并不只包含可承接、可完成、可评价的任务。
2. 交友、经验分享、问答、失物招领、组队等场景更接近“发帖与回复”。
3. 即使部分需求可以抽象为任务，不同类型内容也不一定拥有相同字段和生命周期。
4. 如果把所有内容强行塞进 `Task`，会导致 `Task` 类职责过重，也不利于后续扩展。

因此，本修改稿将核心模型调整为：

```text
用户 -> 发帖 -> 回复 / 互动 / 可选业务扩展
```

其中 `Post` 是平台最核心的内容实体，`Reply` 是最基础的交流方式。`TaskExtension` 只作为某些帖子需要“接单、酬劳、完成确认、积分评价”时的可选扩展，而不是所有用例的核心。

## 2. 设计范围说明

当前 P3 阶段优先覆盖以下核心能力：

```text
用户认证与档案 -> 发布帖子 -> 浏览/搜索/筛选帖子 -> 回复交流
-> 可选报名/申请 -> 可选任务化处理 -> 评价/信用 -> 举报/治理
```

暂缓深入设计的能力包括：复杂推荐算法、真实支付、积分商城、完整私信系统、对象存储、Redis、MQ、Elasticsearch、复杂处罚策略等。

## 4. 用户与身份模块

### 4.1 User

**职责：** 表示平台用户账号，承担登录身份、角色、认证状态等基础信息。

| 属性 | 类型 | 说明 |
|---|---|---|
| `id` | `Long` | 用户唯一标识 |
| `username` | `String` | 登录名或账号名 |
| `passwordHash` | `String` | 加密后的密码 |
| `phone` | `String` | 手机号，可选 |
| `email` | `String` | 邮箱，可选 |
| `role` | `UserRole` | 用户角色 |
| `verificationStatus` | `VerificationStatus` | 校内认证状态 |
| `enabled` | `Boolean` | 账号是否可用 |
| `createdAt` | `LocalDateTime` | 创建时间 |
| `updatedAt` | `LocalDateTime` | 更新时间 |

**关键方法：**

| 方法 | 返回值 | 说明 |
|---|---|---|
| `isVerified()` | `boolean` | 判断用户是否已完成校内认证 |
| `isAdmin()` | `boolean` | 判断用户是否为管理员 |
| `disable()` | `void` | 禁用账号 |
| `enable()` | `void` | 启用账号 |
| `changePassword(String newPasswordHash)` | `void` | 修改密码哈希 |

### 4.2 UserProfile

**职责：** 表示用户公开档案，与账号敏感信息分离，控制前台展示范围。

| 属性 | 类型 | 说明 |
|---|---|---|
| `id` | `Long` | 档案 ID |
| `userId` | `Long` | 所属用户 ID |
| `nickname` | `String` | 昵称 |
| `bio` | `String` | 个人简介，可选 |
| `campus` | `String` | 常驻校区 |
| `skillTags` | `List<String>` | 能力或兴趣标签 |
| `avatarUrl` | `String` | 头像地址 |
| `creditScore` | `Integer` | 信用分或信用等级基础值 |

**关键方法：**

| 方法 | 返回值 | 说明 |
|---|---|---|
| `updateBasicInfo(String nickname, String bio, String campus)` | `void` | 更新基础公开资料 |
| `updateSkillTags(List<String> tags)` | `void` | 更新能力或兴趣标签 |
| `updateAvatar(String avatarUrl)` | `void` | 更新头像 |

### 4.3 CampusVerification

**职责：** 表示校内身份认证记录，支撑可信身份和后台追溯。

| 属性 | 类型 | 说明 |
|---|---|---|

**关键方法：**

| 方法 | 返回值 | 说明 |

## 5. 内容发布模块

### 5.1 Post

**职责：** 表示用户发布的帖子，是平台最核心的内容实体。帖子可以是普通交流、问答、互助、交易、组队、交友、失物招领等类型。

| 属性 | 类型 | 说明 |
|---|---|---|
| `id` | `Long` | 帖子 ID |
| `authorId` | `Long` | 发帖人 ID |
| `categoryId` | `Long` | 所属板块或分类 ID |
| `type` | `PostType` | 帖子类型 |
| `title` | `String` | 标题 |
| `content` | `String` | 正文内容 |
| `campus` | `String` | 关联校区，可选 |
| `location` | `String` | 关联地点，可选 |
| `status` | `PostStatus` | 帖子状态 |
| `pinned` | `Boolean` | 是否置顶 |
| `replyCount` | `Integer` | 回复数 |
| `likeCount` | `Integer` | 点赞数 |
| `favoriteCount` | `Integer` | 收藏数 |
| `createdAt` | `LocalDateTime` | 创建时间 |
| `updatedAt` | `LocalDateTime` | 更新时间 |

**关键方法：**

| 方法 | 返回值 | 说明 |
|---|---|---|
| `publish()` | `void` | 发布帖子 |
| `hide()` | `void` | 隐藏帖子 |
| `close()` | `void` | 关闭帖子，不再接受回复或参与 |
| `reopen()` | `void` | 重新打开帖子 |
| `increaseReplyCount()` | `void` | 增加回复数 |
| `isOpen()` | `boolean` | 判断帖子是否仍可互动 |
| `isWrittenBy(Long userId)` | `boolean` | 判断用户是否为作者 |

### 5.2 Reply

**职责：** 表示帖子下的回复或评论，支撑平台基本交流。回复可以是普通评论，也可以是问答场景下的回答。

| 属性 | 类型 | 说明 |
|---|---|---|
| `id` | `Long` | 回复 ID |
| `postId` | `Long` | 所属帖子 ID |
| `authorId` | `Long` | 回复人 ID |
| `parentReplyId` | `Long` | 父回复 ID，用于楼中楼或追评，可为空 |
| `content` | `String` | 回复内容 |
| `accepted` | `Boolean` | 是否被采纳，适用于问答类帖子 |
| `status` | `PostStatus` | 回复状态，可复用内容状态 |
| `likeCount` | `Integer` | 点赞数 |
| `createdAt` | `LocalDateTime` | 创建时间 |
| `updatedAt` | `LocalDateTime` | 更新时间 |

**关键方法：**

| 方法 | 返回值 | 说明 |
|---|---|---|
| `hide()` | `void` | 隐藏回复 |
| `markAccepted()` | `void` | 标记为采纳回答 |
| `isWrittenBy(Long userId)` | `boolean` | 判断用户是否为回复作者 |

### 5.3 PostCategory

**职责：** 表示平台板块或分类。当前阶段可设计为实体，便于后续调整分类，不必每次修改枚举代码。

| 属性 | 类型 | 说明 |
|---|---|---|
| `id` | `Long` | 分类 ID |
| `name` | `String` | 分类名称 |
| `description` | `String` | 分类说明 |
| `enabled` | `Boolean` | 是否启用 |

**关键方法：**

| 方法 | 返回值 | 说明 |
|---|---|---|
| `enable()` | `void` | 启用分类 |
| `disable()` | `void` | 禁用分类 |
| `rename(String name)` | `void` | 修改分类名称 |

### 5.4 PostType

**职责：** 表示帖子类型，用于区分不同内容模式。

```text
GENERAL          普通交流
QUESTION         问答咨询
HELP_REQUEST     互助求助
TRADE            二手交易
LOST_FOUND       失物招领
TEAM_UP          组队协作
FRIENDSHIP       交友扩列
TASK             任务/悬赏
```

说明：`TASK` 不是平台的唯一核心，只是帖子类型之一。只有该类型或类似类型的帖子才需要绑定 `TaskExtension`。

## 7. 可选业务扩展模块

### 7.1 TaskExtension

**职责：** 表示任务型帖子的扩展信息。它不独立存在，而是绑定到某一条 `Post`。只有当帖子需要接单、酬劳、完成确认、积分或信用评价时，才需要创建该扩展。

| 属性 | 类型 | 说明 |
|---|---|---|
| `id` | `Long` | 任务扩展 ID |
| `postId` | `Long` | 绑定的帖子 ID |
| `publisherId` | `Long` | 发布者 ID，可与帖子作者一致 |
| `assigneeId` | `Long` | 被选中的帮助者 ID，可为空 |
| `rewardType` | `RewardType` | 奖励方式 |
| `rewardDescription` | `String` | 奖励说明 |
| `deadline` | `LocalDateTime` | 截止时间 |
| `completionStandard` | `String` | 完成标准 |
| `requiresProof` | `Boolean` | 是否需要完成凭证 |
| `status` | `TaskStatus` | 任务扩展状态 |
| `createdAt` | `LocalDateTime` | 创建时间 |
| `updatedAt` | `LocalDateTime` | 更新时间 |

**关键方法：**

| 方法 | 返回值 | 说明 |
|---|---|---|
| `assignTo(Long helperId)` | `void` | 选择帮助者 |
| `submitForConfirmation()` | `void` | 进入待确认 |
| `complete()` | `void` | 标记任务完成 |
| `cancel()` | `void` | 取消任务扩展 |
| `markDisputed()` | `void` | 标记为争议中 |
| `isAssignedTo(Long userId)` | `boolean` | 判断用户是否为被选中帮助者 |

### 7.2 TaskStatus

```text
OPEN
IN_PROGRESS
PENDING_CONFIRMATION
COMPLETED
CANCELLED
DISPUTED
```

说明：帖子本身是否发布、隐藏、关闭由 `PostStatus` 管理；任务扩展只负责可承接事项的任务状态。

### 7.3 RewardType

```text
FREE
POINTS
CASH
NEGOTIABLE
```

说明：`CASH` 当前仅表示线下协商或小额报酬说明，不表示平台内置真实支付能力。

**职责：** 表示用户对帖子的参与行为。它可以用于任务申请、组队报名、二手交易意向、活动加入等场景，比原先的 `TaskApplication` 更通用。

| `status` | `ParticipationStatus` | 参与状态 |
| `createdAt` | `LocalDateTime` | 创建时间 |
| `handledAt` | `LocalDateTime` | 处理时间 |

**关键方法：**

| 方法 | 返回值 | 说明 |
|---|---|---|
| `accept()` | `void` | 接受参与申请 |
| `reject()` | `void` | 拒绝参与申请 |
| `withdraw()` | `void` | 参与者撤回申请 |

## 12. 相比原始草案的主要修改

| 原始设计 | 修改后设计 | 修改理由 |
|---|---|---|
| `Task` 是平台核心实体 | `Post` 是平台核心实体 | 平台更接近发帖交流，而不是所有需求都是任务 |
| `TaskApplication` | `Participation` | 支持报名、申请帮助、组队、交易意向等更通用场景 |
| 所有需求共享任务生命周期 | 只有 `TaskExtension` 拥有任务生命周期 | 避免普通交流、交友、问答被强行任务化 |
| `TaskCategory` 作为枚举 | `PostCategory` 作为实体 | 板块更容易调整，减少新增分类时修改代码 |
| `Report`、`Dispute`、`ModerationCase` 三者并列 | `Report` + `ModerationRecord` | 降低治理模型重复，争议可作为举报/治理场景之一 |
| 帖子交流依赖 `Conversation/Message` | 基础交流改为 `Reply` | 更贴近论坛、问答、小红书式内容互动 |

## 13. 后续讨论点

1. `PostType` 是否需要这么多类型，还是只保留普通、问答、互助、交易、组队几类。
2. `TaskExtension` 是否只绑定 `PostType.TASK`，还是也允许绑定 `HELP_REQUEST`。
3. `Participation` 是否应该区分参与类型，例如申请帮助、报名组队、交易意向。
4. `Reply` 是否需要支持多级回复，还是第一版只支持一层评论。
5. `Attachment.ownerType` 是否应改为枚举，避免字符串类型不安全。
6. `PostInteraction.targetType` 是否应改为枚举。
7. `CreditRecord.sourceType` 是否应改为枚举。
8. `Report` 是否需要支持证据附件。
9. `ModerationRecord` 是否需要单独记录处罚类型。
10. 是否需要保留站内私信。如果保留，应作为后续扩展，不进入当前核心类图。
