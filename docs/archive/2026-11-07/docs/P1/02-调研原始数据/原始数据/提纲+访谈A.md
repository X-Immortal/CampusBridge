# 用户访谈记录

## 一、访谈提纲（问题）

1. 你之前用过哪些类似的校园互助平台或渠道？可以简单说说分别是做什么的吗？
2. 你最近一次使用这类平台或渠道，是因为什么需求？当时的完整过程是怎样的？
3. 在那个过程中，你最看重的是什么？是速度、价格、安全、沟通方便，还是别的因素？
4. 你在使用这类平台时，遇到过哪些不方便或者不满意的地方？
5. 你觉得一个校园互助平台最核心的功能应该是什么？为什么？
6. 如果平台一开始功能不能很多，你觉得最应该优先做的 3 个功能是什么？
7. 对你来说，平台要求校内身份认证这件事，带来的主要好处和顾虑分别是什么？你认为有必要吗？
8. 在互助过程中，你觉得站内聊天有必要吗？如果有必要，你希望它解决什么问题？如果没必要，你更推荐什么沟通方式？
9. 你觉得平台应该怎样判断一个任务算“完成”了？如果双方意见不一致，应该怎么办？
10. 如果这个平台真的上线，你觉得自己最可能首先使用的是哪一类场景？为什么是它？

## 二、访谈记录

### 1. 访谈对象基本情况

- 访谈对象：某大三本科生
- 特点：有校园互助类平台或渠道的使用经历，目前忙于实习

### 2. 访谈内容整理

**问题 1：你之前用过哪些类似的校园互助平台或渠道？可以简单说说分别是做什么的吗？**

受访者表示，自己用过互助群，主要用于找代课；还提到过“校园集市”这类校园交流软件，曾经在上面尝试寻找美赛队友。由此可见，受访者接触过的校园互助渠道较为分散，既包括即时通讯群，也包括较综合的校园交流平台。

**问题 2：你最近一次使用这类平台或渠道，是因为什么需求？当时的完整过程是怎样的？**

受访者提到，自己最近的需求是找代课，通常的做法是先发消息，再等待别人联系。这个过程比较直接，但也说明平台或渠道在任务匹配上更多依赖人工浏览和响应，而不是系统化的智能匹配机制。

**问题 3：在那个过程中，你最看重的是什么？是速度、价格、安全、沟通方便，还是别的因素？**

受访者认为最重要的是效率，也就是能否尽快找到愿意提供帮助的人。相比价格或形式，对他来说“能找到人解决问题”是首要因素。

**问题 4：你在使用这类平台时，遇到过哪些不方便或者不满意的地方？**

受访者表示目前没有特别明显的不满，整体使用感受还可以。这说明现有渠道虽然不够系统，但在某些高频场景下已经能勉强满足部分用户需求。

**问题 5：你觉得一个校园互助平台最核心的功能应该是什么？为什么？**

受访者认为，平台最核心的能力是“满足大家的需要”，具体来说，是通过合适的推送或匹配机制，让最可能帮助求助者的人能够及时刷到相关帖子。由此可以看出，受访者非常重视平台的信息分发效率。

**问题 6：如果平台一开始功能不能很多，你觉得最应该优先做的 3 个功能是什么？**

受访者给出的优先功能是：

1. 跑腿
2. 二手交易
3. 课程评价

这说明在他看来，校园互助平台的早期版本应优先覆盖高频、具体、可快速形成使用习惯的场景。

**问题 7：对你来说，平台要求校内身份认证这件事，带来的主要好处和顾虑分别是什么？你认为有必要吗？**

受访者认为，校内身份认证的好处主要有三点：一是避免无关人员进入平台，二是发生问题时更方便追责或与校方协作，三是整体风险更低。顾虑在于部分用户可能不愿意实名使用。但总体上，受访者认为身份认证是有必要的。

**问题 8：在互助过程中，你觉得站内聊天有必要吗？如果有必要，你希望它解决什么问题？如果没必要，你更推荐什么沟通方式？**

受访者认为站内聊天是有必要的，因为任务需求有时表述不够清楚，需要补充沟通。他还提到，如果频繁要求添加外部联系方式，很多用户可能会感到麻烦，因此站内沟通比反复交换联系方式更方便。

**问题 9：你觉得平台应该怎样判断一个任务算“完成”了？如果双方意见不一致，应该怎么办？**

受访者给出的标准较为简洁，认为应以“用户满意、功能实现”为主要判断依据。这说明平台需要设计较明确的完成确认机制和评价反馈机制，以避免双方对任务结果的理解不一致。

**问题 10：如果这个平台真的上线，你觉得自己最可能首先使用的是哪一类场景？为什么是它？**

受访者表示，自己最可能首先使用的仍然是“找代课”场景。这和他当前忙于实习、时间安排紧张的现实情况直接相关，也说明用户需求会受到阶段性个人处境的显著影响。

## 三、访谈思考

### 1. 从本次访谈中得到的主要启发

1. 对部分用户而言，平台是否“高效匹配到人”比功能是否丰富更重要。相比功能堆叠，用户更在意自己的需求能否快速被看见并获得响应。
2. 身份认证虽然会带来一定隐私顾虑，但在校园场景下依然被认为是必要机制。它不仅影响平台的安全感，也影响后续的纠纷处理和信用体系建设。
3. 站内聊天是有价值的。它的作用不只是提供交流渠道，更重要的是降低沟通门槛，避免用户频繁交换私人联系方式。
4. 受访者提出的优先功能集中在跑腿、二手交易、课程评价，说明早期版本应优先覆盖高频且边界较清晰的校园需求，而不是一开始追求面面俱到。

### 2. 关于“代课需求”应如何看待

备注中提到，受访者当前最强烈的需求是“找代课”。这一点确实值得注意，因为它反映了真实用户需求，但并不意味着平台应当直接支持这类功能。

从项目定位和合规性角度看，“代课”很可能涉及课堂考勤、课程参与、身份替代等敏感问题，具有较明显的灰色属性，甚至可能违反课程纪律或学校管理规定。如果平台公开支持此类需求，容易带来以下风险：

1. 平台被用于规避正常教学管理要求；
2. 平台卷入责任认定问题，一旦出现纠纷难以处理；
3. 平台整体形象受损，不利于后续推广和校内接受度。

因此，我认为这类需求可以作为访谈中观察到的真实现象记录下来，但**不应纳入平台的正式支持范围**。更稳妥的处理方式是：

1. 在需求分析中将其记录为“用户现实中存在的时间替代类需求”；
2. 在产品设计中明确禁止发布涉及代签到、代课、代考试等违反校规或存在争议的任务；
3. 将平台重点放在合规、正当、可公开支持的互助场景上，例如跑腿、失物招领、二手交易、组队协作、信息咨询等。

也就是说，本次访谈里“找代课”这个回答是有价值的，因为它提醒我们：用户确实有“时间紧张、希望有人代为处理事务”的需求。但在产品落地时，我们应当把这种需求重新抽象和筛选，转化为更合适的功能方向，而不是直接支持有争议的具体行为。
