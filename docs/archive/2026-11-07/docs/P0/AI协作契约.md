# AI协作契约

**团队名称：** 请输入文本队  
2026年4月

队名“请输入文本”来源于我们对 AI 使用方式的一个小提醒：如果只是机械地接受默认内容、直接复制粘贴，最后交上去的很可能就只是“请输入文本”式的空壳结果。我们希望用这个名字提醒自己，AI 可以提供草稿、建议和灵感，但真正需要输入判断、补充内容并承担责任的，始终是团队成员本人。任何内容都不能“看起来像对的就直接提交”，而要经过理解、审查和修改之后再进入项目。

为规范本团队在项目开发过程中对人工智能工具的使用方式，明确成员责任，保障项目质量与协作秩序，特订立本契约。团队全体成员应共同遵守。

## 第一条：AI使用原则

1. AI是辅助工具，不是责任主体。项目中的分析、设计、编码、测试和文档工作，最终责任均由团队成员承担。
2. 所有AI输出内容均不得直接视为最终成果，必须经过人工检查、理解和确认后方可使用。
3. 团队成员应保持独立思考，避免对AI工具形成过度依赖。

## 第二条：AI使用范围

### 一. 允许使用AI的场景

1. 头脑风暴、需求梳理、文档初稿生成。
2. 技术资料整理、方案对比、代码示例参考。
3. 一般性编码辅助，如样板代码生成、接口说明整理、注释补充。
4. 测试点分析、测试用例草稿生成。
5. 代码问题排查、报错信息分析与修改建议。

### 二. 禁止直接使用AI输出、需额外审查的场景

1. 核心业务逻辑代码。
2. 涉及权限控制、数据安全、账号信息处理的代码。
3. 数据库表结构设计、关键接口设计。
4. 项目最终提交的正式文档、总结性结论。
5. 团队成员本人尚未理解其含义和作用的内容。

### 三. 完全禁止使用AI的场景

1. 用户调研结果、测试结果、运行结果或课程要求中的事实性内容。
2. 将含有敏感账号、密码或其他不应外泄的信息直接输入公共AI平台。

## 第三条：过程记录要求

1. 团队成员在使用AI工具时，应保留关键Prompt及主要输出结果，便于后续回顾和说明。
2. 所有代码提交应在commit message中标注 `[AI-assisted]` 或 `[Human-written]`。
3. 每个阶段按课程要求记录AI协作反思内容，总结AI的帮助、局限与改进方式。
4. 若AI参与了重要设计、代码生成或测试分析，相关成员应能说明其使用过程及人工修正情况。

## 第四条：代码合入规则

1. AI生成的代码在合入主分支前，必须经过至少一名团队成员的人工Code Review。
2. 对关键模块、核心流程和重要函数，提交者应能够清楚说明代码逻辑与实现原因。
3. 每位成员在每个编码阶段至少完成两个完全手写的核心函数，以保证基本工程能力训练。
4. 对未经审查、本人未理解或存在明显风险的AI生成代码，不得直接合入项目。

## 第五条：违约处理

1. 若成员未按契约要求记录Prompt、标注提交信息、进行必要审查，团队优先采取提醒与补正方式处理。
2. 第一次出现违约时，由团队在例会上口头提醒，并要求当事人在约定时间内补全缺失记录或完成补审。
3. 再次出现违约时，由团队在项目文档中做一次简要登记，并由当事人承担一次额外的人工复查、测试补充或文档整理工作。
4. 若违约行为已经影响项目质量或进度，例如未经审查直接合入代码、提交内容存在明显问题，则应立即回滚或修正相关内容，并由至少一名其他成员协助复核。
5. 本条款的目的在于保障项目质量、维护团队协作秩序，而非进行惩罚。团队应以问题修复和流程改进为优先。

## 附则

1. 本契约自团队全体成员签字之日起生效。
2. 本契约在项目执行过程中如需调整，应由团队成员共同讨论决定。
