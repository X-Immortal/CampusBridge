## 4. 问卷核心结论

### 4.1 高频需求场景

根据对 `Q1` 和 `Q2` 的主题归纳，需求主要集中在以下方向：

- 跑腿 / 代取 / 校内即时事务
- 咨询 / 信息求助 / 经验分享 / 答疑
- 失物招领
- 二手交易 / 出物换物
- 资料共享 / 学习辅导
- 组队 / 搭子 / 拼单 / 拼车

其中，前期统计显示：

- `Q1` 中出现频次较高的主题：跑腿 27 次、咨询 23 次
- `Q2` 中出现频次较高的主题：二手平台 20 次、失物招领 18 次、快递跑腿 16 次

### 4.2 使用意愿与采用前提

| 观察项 | 结果 | 说明 |
|---|---:|---|
| 数值型使用意愿样本 | 41 份 | 对 `Q9` 中纯数字回答单独统计 |
| 平均使用意愿分 | 7.1 / 9 | 整体处于偏高水平 |
| `Q9` 中 7 分及以上 | 28 份 | 高意愿样本占多数 |
| 文本型“使用意愿极高” | 10 份 | 单独保留，不并入均值 |
| 认为需要线上交流 | 48 / 51 | 站内沟通是强需求 |
| 愿意接受积分 | 43 / 51 | 积分机制具备可行性 |

### 4.3 平台治理与收费偏好

- 收费方式偏向低门槛：`完全免费` 17 份、`部分功能收费` 14 份、`自愿捐款` 11 份、`收手续费` 7 份。
- 开放题中频繁提及的治理诉求包括：
  - 内容审核
  - 语言规范
  - 用户隐私保护
  - 举报 / 拉黑 / 申诉
  - 信用评价与违约惩罚
  - 过期内容清理
  - 交易纠纷处理
- 建议中多次出现“少广告、简流程、标签便于搜索、常驻管理员、合理匿名、根据专业或年级做定制化服务”。

### 4.4 任务完成标准

`Q13` 的开放回答基本集中在以下机制：

1. 双向确认：求助方与帮助方共同确认任务完成。
2. 凭证留存：拍照、上传完成证明或站内消息记录。
3. 双向评价：完成后互评，形成信用记录。
4. 平台仲裁：有争议时由管理员介入。
5. 托管与超时规则：部分回答提出预付报酬托管、超时自动确认等机制。

这说明“完成判定”不能只靠单方口头确认，平台需要提供结构化闭环。

## 6. 访谈结论摘要

### 6.1 共同发现

1. 平台首先要解决“快速找到合适的人”，而不是单纯堆叠功能。
2. 身份认证、评价信用、举报仲裁、可追溯记录是校园场景下的信任基础。
3. 用户普遍支持站内沟通，希望减少交换私人联系方式的成本。
4. 流程必须尽量短，发布任务不能像填长表单，否则用户宁愿回微信群。
5. 用户高度关注能力、口碑、距离、校区、历史记录、响应速度等筛选条件。

### 6.2 差异化发现

- 时间紧张的用户更关注“效率”和即时响应。
- 学习互助型用户更看重本校经验、能力标签与成功率。
- 事务代办型用户更在意实名、留痕、违约惩罚与追责能力。
- 即时跑腿型用户更看重顺路模式、少广告、少步骤与临时应急支持。

### 6.3 风险边界

- 访谈中出现“代课”“签到”等真实需求，但这类场景具有明显合规风险。
- 后续正式需求中若保留该类场景，必须加上实名、留痕、审核、举报、处罚、管理员介入等强约束。

## 7. 面向需求分析的直接结论

本轮调研可直接支持以下需求方向：

1. 平台必须支持校内身份认证，但前台展示需兼顾隐私保护。
2. 平台必须提供快速发布、搜索筛选、精准匹配、站内沟通四项核心能力。
3. 平台必须具备任务生命周期闭环：发布、申请/接单、沟通、完成确认、评价、举报、仲裁。
4. 平台应支持积分、小额报酬或互帮互助等多样激励，不宜默认高收费。
5. 平台应重点覆盖跑腿、咨询答疑、失物招领、二手、学习互助、组队协作等高频需求。
6. 平台需要明确敏感场景与违规任务边界，尤其是课堂类争议协助请求。
